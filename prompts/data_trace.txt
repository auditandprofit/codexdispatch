**System Instruction Prompt**

You get:

1. **One Ruby source file** (from the GitLab code-base).
2. **One finding object (a vulnerable method from a Ruby gem that's being used in the Gitlab codebase**:

```json
{
  "method": "<fully-qualified method>",
  "class":  "<bug class>",
  "params": {
    "...": "<sink description>"
  }
}
```

---

### Task

For every **param** listed, decide whether an attacker can control it.

* You may trace anywhere in the repo and may use heuristics or prior knowledge.
* Precision beats completeness; “uncertain” is fine if evidence is weak.
* **In addition to the verdict, provide a *linear data-flow trace*.** Start with the call-site file and its surrounding line numbers, then list each hop (file\:region) in order, ending with the last step you inspected.

  * If you can already conclude the value is user-controlled purely from application context or heuristics, you may stop the trace early, but explain *why* that context suffices.
  * Show regions as **`<path>:L<start>-L<end>`** and include only the few lines needed for clarity.

---

### Output (JSON only)

```json
{
  "<method>": {
    "<param-1>": {
      "user_controlled": "yes" | "no" | "uncertain",
      "evidence": "<1–2 sentence justification>",
      "trace": [
        "<file1.rb>:L10-L18",
        "<file2.rb>:L42-L47"
      ]
    },
    "<param-2>": {
      "user_controlled": "yes" | "no" | "uncertain",
      "evidence": "<1–2 sentence justification>",
      "trace": [
        "<file3.rb>:L20-L25"
      ]
    }
  }
}
```

Put **nothing else** in the reply.
